# Database Internals 학습 목표

## 장기 목표

『Database Internals』의 핵심 원리를 온전히 이해하고, 낯선 데이터베이스도 내부 동작을 스스로 추론·검증하며, 서로 다른 데이터베이스가 같은 문제를 어떤 구조와 트레이드오프로 해결하는지 비교할 수 있는 수준에 도달한다.

목표는 특정 데이터베이스의 기능이나 설정을 암기하는 것이 아니다. 전체 학습을 관통하는 질문은 다음과 같다.

> 주어진 워크로드와 보장 수준에서, 데이터베이스는 데이터를 어떻게 저장·변경·노출·복구·유지·분산하며, 그 대가를 어디에 배치하는가?

이 질문을 `요구사항 → 물리적 저장과 탐색 → 변경 비용 → 동시성과 가시성 → 장애와 복구 → 시간 경과와 자원 경쟁 → 여러 노드 → 설계 선택의 평가` 순서로 분할한다. 앞 단계의 단순한 데이터베이스에 현실의 압력을 하나씩 추가하고, 마지막에 전체 설계의 적합성과 트레이드오프를 평가한다.

1. **무엇을 해결해야 하는가?** 데이터 모델과 point lookup·range scan·join·aggregation 같은 접근 패턴, latency·throughput·freshness, 필요한 정합성과 내구성을 먼저 정의한다.
2. **데이터를 어떤 물리 구조로 표현하고 필요한 바이트를 어떻게 찾는가?** Page, record, file, B+tree, LSM-tree, Heap, Columnar, index와 cache를 배운다. 아직 동시 실행이나 장애는 없다고 가정한다.
3. **데이터 변경 비용을 언제, 어디에서 지불하는가?** In-place update와 append, buffer와 MemTable, immutable file, read·write·space amplification을 비교한다.
4. **여러 읽기와 쓰기가 겹칠 때 누구에게 어떤 버전이 보여야 하는가?** Lock, MVCC, Sequence Number, Snapshot, isolation과 정상 실행 중의 atomicity를 다룬다.
5. **실행 도중 멈췄을 때 무엇이 살아남고 어떻게 복구되는가?** WAL, redo·undo, checkpoint, commit, crash atomicity와 client acknowledgement의 의미를 배운다.
6. **오래 실행되고 작업들이 유한한 자원을 경쟁해도 어떻게 성능을 유지하는가?** Compaction, Vacuum, Purge, Merge, tombstone 제거, cache·thread·I/O 관리, per-instance와 per-host 제어, backpressure와 stall을 다룬다.
7. **한 노드를 넘으면 데이터의 책임과 진실을 어떻게 나누는가?** Partitioning, replication, consistency, quorum, consensus, distributed transaction과 distributed execution을 배운다.
8. **그래서 이 시스템은 어떤 문제에 적합하며, 무엇을 얻고 잃는가?** Embedded engine·DBMS·managed service의 책임 경계를 구분하고, RocksDB부터 HeatWave까지 OLTP·OLAP·HTAP의 저장 및 실행 구조를 비교한다.

## 도달해야 할 이해 수준

학습을 마치면 다음과 같은 질문을 원리부터 설명할 수 있어야 한다.

- 이 데이터베이스는 왜 B+tree, LSM-tree, Heap, Columnar 구조 중 하나 또는 여러 개를 선택했는가?
- 쓰기량이 급증하면 어떤 구조에서 무엇이 병목이 되는가?
- PostgreSQL과 InnoDB의 MVCC는 RocksDB Snapshot의 버전 가시성과 무엇이 다른가?
- StarRocks와 ClickHouse의 Merge 또는 Compaction은 RocksDB Compaction과 무엇이 같고 다른가?
- SingleStore와 HeatWave는 OLTP 데이터를 어떻게 분석 경로에 노출하며, 데이터 최신성을 유지하는 비용은 어디에서 발생하는가?
- 주어진 워크로드와 장애 조건에서 어떤 구조가 적합하며, 그 선택으로 무엇을 얻고 잃는가?

## 학습 원칙

- 『Database Internals』을 전체 개념의 뼈대로 사용한다.
- 주 근거는 각 제품의 공식 논문과 공식 문서에 적힌 자연어 설명이다.
- 현재 upstream 코드는 논문과 공식 문서만으로 부족한 동작을 확인하거나 자연어 설명을 구체화하는 보조 근거로만 사용한다. 코드에서 발견한 세부 구현을 이유로 학습 범위를 임의로 확장하지 않는다.
- 논문의 직접 주장, 공식 문서의 보장, 현재 구현으로 확인한 동작, 일반적인 데이터베이스 모델과 추론을 구분한다. 원문에 직접 적히지 않은 연결이나 결론은 추론으로 표시한다.
- DynamoDB와 HeatWave처럼 내부 구현이 공개되지 않은 부분은 추측하지 않고 `공개된 보장`, `알려진 구조`, `알 수 없음`으로 나눈다.
- 제품별 옵션은 원리를 이해하는 데 필요한 범위로 다룬다.
- 호스트 전체 자원 관리처럼 데이터베이스의 근본적인 설계 경계와 트레이드오프를 보여주는 내용은 단순 운영·튜닝으로 분류해 제외하지 않는다.

## 학습과 통과 절차

각 과정은 이전 학습을 바탕으로 새로운 내용을 이해하고 자기 언어로 재구성하는 것을 목표로 한다.

### 범위와 선행 학습

- **이전 내용 참조:** 이미 학습한 개념·근거·평가는 이전 과정의 해당 장·절을 링크하여 갈음한다. 재설명·원문 재인용·기초 개념의 반복 평가는 생략한다.
- **현재 과정의 핵심:** 새롭게 추가되는 개념, 판단 조건, 보장과 책임의 경계, 선행 개념과의 새로운 연결을 설명하고 평가한다. 핵심에 집중하되 현재 과정의 필수 내용은 빠뜨리지 않는다.
- **선행 이해 보완:** 진행 중 이전 개념의 오해가 드러나면 해당 부분만 돌아가 보완한다.

합의된 종합 복습·종료 시험은 제품별 지침에 정해진 범위를 따른다.

### 학습과 평가

1. **학습 범위 고정:** 현재 과정의 중심 질문, 새로 배울 하위 주제와 주 근거, 참조할 이전 과정의 장·절을 먼저 정한다.
2. **개념 학습:** 설명자는 학습 범위로 정한 새 내용과 연결 관계를 모두 설명한다.
   - **원문과 설명:** 핵심 주장마다 공식 논문이나 공식 문서의 자연어 원문을 문맥과 함께 발췌하고, `원문 발췌 → 직역 → 시간순 상태 흐름 → 보장·비보장·알 수 없음` 순서로 설명한다.
   - **예측의 역할:** 학습 전 예측은 필요할 때만 사용한다. 새 내용을 예측에서 맞혔거나 설명자가 요약할 수 있다는 이유로 원문 학습을 생략하지 않는다.
3. **통과 기준 공개:** 개념 학습을 마치면 무엇을 설명할 수 있어야 하는지 구체적으로 공개한다. 정해진 문구의 암기가 아니라 구성 요소 사이의 인과관계, 보장과 책임의 경계를 평가한다.
4. **첫 재구성:** 학습자는 자료와 모범 답안을 보지 않고 자기 언어와 예시로 현재 과정의 학습 범위 전체를 정리한다.
5. **오개념 진단:** 설명자는 첫 정리를 기준별로 `충족`, `핵심 누락`, `잘못 이해함`으로 판정한다. 설명하지 않은 내용을 알고 있다고 추정하지 않으며, 정답을 대신 작성하지 않는다.
6. **문제 풀이:** 누락이나 오개념마다 이를 드러낼 수 있는 구체적인 상태 흐름, 반례 또는 비교 문제를 제시한다. 학습자는 문제를 풀며 기존 설명이 왜 부족했는지 확인한다. 답을 내기 어려울 때는 해당 원문과 개념만 다시 학습한 뒤 다른 문제로 재확인한다.
7. **오답노트와 재구성:** 학습자는 `처음 이해한 내용 → 문제에서 드러난 오류나 경계 → 수정한 이해`를 자기 언어로 정리하고 현재 과정의 학습 범위 전체를 다시 작성한다. 모든 기준을 충족할 때까지 5~7단계를 반복한다.
8. **통과 판정:** 최종 정리와 필요한 오답노트가 공개된 모든 기준을 충족하면 통과로 판정한다.

### 상태와 기록

과정별 상태는 다음 세 가지로 관리한다.

- `미학습`: 정보 학습을 시작하지 않았다.
- `학습 중`: 설명을 들었지만 검증 전이거나 일부 통과 기준을 충족하지 못했다.
- `통과`: 학습자가 자기 언어로 설명하여 공개된 통과 기준을 모두 충족했다.

진행과 기록은 다음 원칙을 따른다.

- 한 번에 하나의 과정만 학습한다. 여러 세션이 필요하더라도 현재 과정이 끝나기 전에 다음 과정을 시작하지 않는다.
- 현재 과정이 `통과`하기 전에는 해당 과정의 학습 기록을 커밋하지 않는다.
- 통과하면 제품별 학습 문서에 학습자가 자기 언어로 작성한 최종 정리, 학습에 유효했던 오답노트, 최종 평가와 통과 상태를 하나의 커밋으로 기록한 뒤 다음 과정으로 넘어간다. 실패한 초안과 대화의 모든 시행착오를 그대로 옮기지는 않는다.
- 가능하면 `하나의 과정 → 하나의 세션 → 하나의 통과 커밋` 단위로 진행한다.

## 원문·출처 중심의 노션 초안

학습자가 “소제목, 원문, 출처만으로 노션 초안”을 요청하면 다음 형식을 적용한다. 개념 학습은 위의 학습·평가 절차를 따른다.

- 합의된 소제목과 순서를 그대로 유지한다.
- 일반 Markdown으로 제공하며, 출처별 접기를 HTML의 `<details>`와 `<summary>`로 나눈다. 접기 제목에는 출처 링크를 넣고, 안에는 원문을 인용한다.
- 원문은 대상 개념의 역할과 보장 조건을 이해할 수 있는 문맥을 보존해 발췌한다.
- 번역·요약·해설 없이 복사할 수 있는 형태로 제공한다.

아래 예시의 Markdown 구조를 따른다.

```markdown
## 1. WriteBatch의 원자성과 isolation은 무엇이 다른가?

<details>
<summary><a href="https://github.com/meta/rocksdb/blob/main/include/rocksdb/write_batch.h">write_batch.h — WriteBatch</a></summary>

> WriteBatch holds a collection of updates to apply atomically to a DB.

</details>
```
